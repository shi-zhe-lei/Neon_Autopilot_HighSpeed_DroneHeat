# Main runtime / 主运行时

## 中文

物理光照更新还把已经解析的玩家道路帧交给驻留道路池，采样该隧道已有灯光底值，再将同一个预分配结果传给船体的 `setTunnelBounce`。此呈现链与 High 局部灯清单独立，Low/Medium 仍不扫描或创建动态灯。室外、失配或未驻留帧立即清零，暂停刷新不推进灯光动画，采样不修改路线、船体颜色、生命或驾驶状态；调试 DOM 公开接收的标量与身份是否有效。

普通驾驶相机将跟随朝向与 FOV 单独保存：下一帧阻尼前恢复，在最终侧倾与 HUD 入镜保护前捕获。纠偏不再回写 `cameraLookTarget / cameraLookOffset`，最终镜头和逐帧侧倾也不进入跟随状态，消除道路左右边缘的周期性反馈。保护仅修正实际越界量，视野余量随剩余误差连续归零，避免首次触边时固定推开或缩放。Film、车头和自由观察清空此快照，返回时从当时镜头继续；船体、镜头位置、画质和驾驶权威不变。

HUD 投影按显示内容去重：速度数字/ARIA 以语言、整数速度和速度状态为签名；可见指针仍对每帧真实速度更新。`hudPrimaryBody` 收起时跳过隐藏的 SVG 与 RPM 详细仪表，展开的下一帧立即恢复当前权威状态，两处移动速度不受影响。核心仪表与按键追踪只跳过完全相同的投影；可见 RPM、快速按键、手动/自动切换、跳跃保持到期和腾空计时仍即时刷新。所有缓存仅属于呈现，不更改物理、控制或玩法时钟。

HTML 的 `data-camera-hud-occluder` 标记实际表面。启动、视口、展开、语言和尺寸观察事件合并为布局事务，缓存相对 Canvas 的 `cameraHudSafeRect`；相机每帧只读取缓存，不能测 DOM。抽屉两侧、上下空隙以实际矩形求解，狭长侧缝不会仅凭面积胜过可用航道；完全无空白时明确标记 `blocked`。视口事务先更新 CSS 和缓存再使用新宽高比，卸载取消测量队列并断开观察器。只读诊断公开布局 revision、测量次数与船体投影；调试模式也写入既有 `app.dataset.neonDiagnostics`。

纹理过滤原始值改由 `WeakMap` 保存，避免长期保留已释放图块纹理。Low/Medium 的流式加载直接保留新纹理作者设定，不为相同过滤值整场景遍历；显式切档仍完整恢复原值。High 在绘制前同时检查 GPU 数量和道路池纹理发布 revision，确保同数量的新图块/标牌替换也在首帧取得设备最大各向异性；环境 HDR 内容刷新不冒充新纹理所有权。像素预算、阴影分辨率与材质档位不变。

物理灯光交接使用本帧真正消费的 `simulationFrameDt`，只在正在行驶且未暂停/结算时传给 `physicalLightingRig.update({ dtSeconds })`；启动、预编译和暂停重绘传 `0`。这样同一经过时间在不同刷新率下得到相同交接亮度，渲染调用次数不能推进灯光时间，也不改变玩法时间或路线权威。

运行时只在贴地稳定帧发布 CPU 路网租约并执行回收；腾空期间只累计延迟诊断，绝不释放起飞/目的道路。租约合并当前与上一游标、主/候选/对向 PathPlan、道路池 resident/已呈现/Film 前图块、落地握手及仍存活的障碍和烛光实体。固定世界景物的独立直行游标随当前图块重基，并在保留上一图块后压缩前缀，因此绝对坐标不变但不再持有开局以来全部路线。调试快照同时公开 CPU registry、PathPlan 压缩、扫描候选与 WebGL resident 证据，避免把 CPU 拓扑积累误报成 GPU context 丢失。

保存主循环、输入、相机、HUD 与各模块编排。它在全部依赖加载后最后执行，并保持现有跨模块调用顺序。

初始运行时只维护一个启动加载状态；开始页保持 `hidden + inert`，开始按钮保持原生禁用。加载阶段只在对应工作真实完成时依次提交“模块 / 世界 / 道路 / 图形 / 首帧”，不得根据墙钟、循环次数或估算值生成百分比。六条提示使用独立 UI 游标，并且仅在阶段索引严格前进时同步换到下一稳定 tip ID；重复提交同阶段不得换条。提示没有 `setTimeout` / `setInterval`，不消费玩法 RNG，也不能写入 readiness、阶段、路线、天气、画质或首局状态；语言切换只按当前 ID 重绘，不推进提示或加载。运行时通过 RAF 轮询等待首段 current/next 道路共同报告 ready，随后只为玩家已选画质执行 `compileAsync`（不支持时才使用兼容编译路径）及编译/链接诊断，再提交首张完整画面并成功启动动画循环。普通入口必须在同一发布事务中先启用开始按钮、再显示开始页、最后停用并隐藏加载层；这个顺序保证任何可见开始页都能直接开始。任一模块、世界、道路、图形、首帧或动画初始化失败仍进入统一致命边界，不能留下可点击的半初始化页面。

图形阶段在调用 `compileAsync / compile` 前必须先执行飞船模块的 `prepareInvulnerabilityShieldCompilation()`，使碰撞后才会显示的结界外壳、星轨与实例锚点以零透明度进入同一次着色程序准备；无论编译成功或失败，`finally` 都调用 `resetInvulnerabilityShieldPresentation()`。这一顺序保证第一次普通损伤只改变可见状态，不在玩法帧内首次编译结界，也不会把编译态泄漏进开始页。

Windows 混合显卡机器创建 WebGL 时先请求 `high-performance`；若驱动拒绝该适配器提示，运行时只再用 `default` 偏好重试一次，抗锯齿、颜色、物理与玩家选择的画质合同全部不变。两次均失败才发布 `webgl-renderer-create-failed`，错误消息保留两次尝试及原因；运行时在异常越出外部脚本前先把完整错误提交恢复页，随后仍向上抛出，避免直接 `file://` 把根因净化掉。

有效更新提示高于启动加载层：就绪只允许启用“仍要游玩”，不能越过提示提前显示开始页。普通入口在玩家继续后发布已就绪开始页且不解锁音频；只有显式 `autostart=1` 可在继续后直接取得提交令牌而不闪现开始页，并保留加载层直至首个玩法帧成功。致命恢复高于两者并使所有待发布事务失效。

`#overlay` 是 `launch / pause / gameover` 共用的唯一模态层。继续或确认重开必须在画质、天气、场景或运行序号等副作用之前取得唯一提交令牌，把阶段从 `ready` 切到 `committing`，并锁定天气、画质、暂停重开按钮和手册。暂停层的“重新开始本局”与 `R` 只打开独立二级 `alertdialog`，不预留提交令牌也不改玩法状态；默认焦点在取消，`Esc` 或取消关闭弹层、保持原局暂停并把焦点还给开启者，只有确认按钮会先关闭弹层再进入唯一 `resetGame()` 权威。运行时在公开暂停层前先提交 `data-overlay-mode="pause"`，让卡片以扣除四向安全区后的动态视口可用矩形水平、垂直居中；手机竖屏与矮横屏都不得复用启动页贴底位置，内容超高时只允许卡片内部滚动。`resetGame()` 与恢复暂停均拒绝确认层打开时的绕过调用；致命恢复会先关闭确认层。只有运行中、未暂停、未结算的首个玩法帧成功呈现后才可撤层、解除背景 `inert` 并把焦点交给画布；暂停、结算、页面隐藏或致命恢复会使旧提交失效。手册、曲库或重开确认开闭时按当前真值重新计算 `inert` 与 `aria-hidden`，再把焦点恢复到仍可用的开启者或安全画布。

飞行手册 v18 只编排现有状态，不拥有第二份玩法权威。玩家可见的 Essential/“必会”是初始范围，Full 范围在界面中标为 Complete/“完整”；内部 `essential` 的 `16` 个决策优先 ID 来自完整 `43` 项玩家账本的稳定子集，切到 `all` 只解除其余 `27` 个参考节点的 `hidden`，不创建功能、调用控制器或改变航程。打开时 `captureGuideContextSnapshot()` 只采样一次当前阶段、由 P/M 决定的有效横向/纵向权威、电影镜头状态、速度、生命/烛光、制动和下一步；`refreshGuideContext()` 与手机紧凑摘要只按这份冻结记录重绘，语言切换不会重新采样移动中的航程，也不会形成逐帧遥测源。五步 60 秒快速上手是静态说明。四状态矩阵按优先级解释权威：P 关闭、M 关闭是 W 手动；P 关闭、M 开启是无目标速度上限的持续满油门；P 开启时领航在两种 M 偏好下都统一拥有选路、转向、加速、滑行和制动权威，M 只保存退出 P 后的偏好。F 电影模式只改变镜头，不覆盖这套权威。只要 P 开启，普通障碍、弯道与对向道路边界制动都由同一纵向权威处理。上一章/下一章按四个 ARIA 标签循环并复用同一选中 tab 权威，每次切章把唯一内容滚动区归零；运行时按标签实际几何发布横向或纵向 `aria-orientation`，只接受对应轴方向键，`Home/End` 在两种布局都可用。打开手册会保存实际开启者、撤下曲库、隔离背景并把焦点移到当前选中章节；关闭、返回或 `Esc` 隐藏整页手册覆盖层，重新计算隔离状态，并优先把焦点还给启动、暂停或结算中的原开启者，开启者失效时才回退到安全画布。手机与矮横屏页脚隐藏同页头关闭键重复的返回控件，但关闭与 `Esc` 的归还焦点合同不变。人工天气开发控件不在 `43` 项玩家账本内。

实时飞行甲板的 `30` 个语义按钮（桌面 HUD `12` 个、移动 HUD `13` 个、触控驾驶 `5` 个）通过 `data-flight-deck-control + tabindex="-1"` 退出顺序焦点，运行时同时把任何飞行态 `focusin` 归还给 Canvas。所有模态、启动、暂停、结算、更新和恢复守卫必须先于该门执行；只有真实运行层拦截 `Tab / Enter / NumpadEnter`，并让方向键与 `SPACE` 在取消浏览器默认行为后继续进入同一驾驶分发。触控持续键只保留 pointer capture，不能再注册 Enter/Space 的目标级 keydown/keyup；辅助技术仍可用零明细 click 获得一次有界脉冲。关闭飞行中的曲库回到 Canvas，而启动、暂停和结算层仍恢复各自可用开启者。

运行时在启动或暂停时原子切换灯光、后处理、道路、地貌、世界与飞船的预建画质变体；失败时恢复上一档。Low/Medium 把冻结空灯具列表直接交给灯光权威，既不调用道路池的 emitter getter，也不运行近距动态隧道聚光和局部阴影；灯罩、扩散片及原批次静态照度仍持续发亮。只有 High 聚合当前可见的 authored 灯具记录并启用这一动态细节。Low / Medium / High 道路统一保留 `0.68` 的干燥反照率余量，积雪只把该系数连续抬到 `0.96`，High 再乘 `0.97`，避免 ACES 与雾把桥面曝成白板；实体积雪网格仍是空间覆盖权威。High 地貌程序把浮动原点通过共享 uniform 加回渲染相对坐标，保证颗粒、粗糙度、微法线和明暗斑块固定在绝对世界并相对飞船运动。画质诊断分别公开 profile 的 `dynamicLocalFixtureLights` 开关、运行时向灯光 rig 提交的实际开关与记录数；High 诊断还公开请求/实际阴影、DPR/像素预算、各向异性、MSAA/FXAA、AO、Bloom、RenderTarget 数量及地貌程序坐标锚定误差。远山另公开真实层数、常驻网格、可见绘制组、实例、morph target、轮廓签名、自发光违规、世界锚滞后和 morph 权重。FPS 保持只读，不能触发降档。

运行时向桥梁生成器和世界景物层提供与画面完全同源的地貌高度采样器。查询由绝对世界坐标定位 `96m` cell，逆转该实例的离散旋转，应用同一 biome/ecotone relief scale，并在实际地貌网格三角形内插值；生产桥墩和地面景物都不得退回道路 Y 或固定 Y。道路板净空同时提交柱体的 `verticalEnvelope`，横倾板底按 `thickness / abs(upY)` 换算到世界竖直高度。只读支撑诊断与逐实例矩阵审计共同锁定单侧传力盖梁、宽跨双柱门架、地基接触和顶接；当前完整记录为 `816` 条运行时支撑和 `239` 根常驻支撑，取代旧二维口径的 `606 / 237`。

保底连续道路的互通桥也服从 `SKY_ROUTE_SCENERY_CONTRACT` v2，而不是保留一套现代灰色桥墩。原 `4 / 2` 个桥墩/横梁实例容量及全部位置、比例、道路净空和玩法矩阵不变；柱身改为 `16` 层、`32` 边的封闭风蚀暖石拓扑，横梁改为保持原 `±0.5 × ±0.38 × ±0.5` 局部包络的 `16` 点、`6` 轴环封闭花瓣菱形石梁。共享材质为 `metalness=0.01 / roughness=0.94 / clearcoat=0.02 / emissive=0`，并在启动时对 v2 上限失败即停。真实卸载以对象身份去重并恰好一次释放两份桥梁几何、共享石材、接触阴影共享几何/源材质及活跃与池化阴影的克隆材质；分类障碍与烛光已经取代的旧模板材质只在不可达回滚构建器被显式调用时才惰性创建，不再占用生产启动资源。

运行时验证六境分类后，在首帧前预热烛光与障碍视觉工厂；每个静态/动态障碍家族分别预热 `48 / 24` 根，每个可收集烛光家族固定预热 `96` 根、总计 `1_152` 根。障碍、船流与烛光三个生成通道在低于 `24m/s` 时都按真实 `speed / 24` 缩放，停车时距离与生成时钟完全冻结，不能再以虚构巡航速度累积实体。单次障碍事件最多同步发布基础、直道岔路副本和对向预览三根同族主视觉；运行时在首次取得前检查完整三根容量，容量不足则跳过整组，晚到岔路扩展或对向预览也在取得前独立检查，因此不会留下半组或把对象池耗尽变成帧错误。生成逻辑仍唯一拥有里程、路线、碰撞、奖励、速度、生命与动态障碍轨迹。每个已被主路生成器接受的障碍或烛光都会确定性投影并复制到目的图块的完整对向反向代理及跨线边前 `1,080m` 稳定别名；复制不推进 RNG、生成时钟、主路计数或主路 ID 序列。副本在落地前已可见，但路线距离与碰撞保持无穷，不参与奖励、威胁或主路生成布局。未取得路线权威的动态障碍按 placement 中的 `crossoverEdgeId + stabilizationLength` 建立运动门，在未就绪桥段前沿服务制动曲线减速并停住；静态障碍和烛光不经过该运动门。对向路线采用时，运行时不重生成实体，而是原位保留 edge station、横向偏移、ID、动态分组、相位和原始纵向速度，释放运动门并切换 `PathPlan` 与碰撞权威；跨线后的正常 horizon 生成再继续接管。障碍公共根只写世界位置并保持单位缩放和零旋转，工厂只动画无碰撞提示层；烛光公共根只跟随路线姿态，工厂只动画内部烛芯、火焰、光环与尾迹。画质切换原子转发给两座工厂，卸载时统一释放；诊断分别公开分类数量、活跃/池化数量、对向预热数量与失败数、容量抑制计数、预热分配、真实三角上限和帧内资源分配计数。

运行时是地表物理的唯一写入权限。每个物理帧先在 `updateLongitudinalControl()` 内消费上一帧扫掠接触的有界压力减速度，再让手动驾驶、自动领航和预测通过 `getPlayerKinematics()` 共用同一组横向倍率；地表模块、渲染器和音频都没有反向写入口。完成本帧移动和真实灯光后，运行时把前后里程、横向位置、速度、侧滑、贴地状态和净空交给地表模块，以飞船压力足迹计算下一帧响应。该一帧延迟避免预测性位置回写，并保持纵向速度只有一个权威写入路径。地表姿态包只在运行时叠加到可视船体，减少动态时归零，不改变碰撞代理或路线。

垂直运动从上一份路线游标/里程扫到本帧路线状态，并按完整帧比例插值横向位置，避免弯坡或银行角道路只采终点车道。普通空中帧和实体跳台坡唇后的剩余时间都调用同一个 `sweptVerticalContact()`；平台先在真实唇口建立切线离地速度，再把唇口至帧末的距离和时间交给扫掠器，不能用裸弹道终点提前返回。进入实体跳台 corridor 时，运行时先取得目的图块的不可变落地握手；只有准确普通签名同时完成、active、通过一次真实渲染帧且同一 token 的对向碰撞边存在，平台才成为实体支撑。若在船体首次接触桌面时仍未就绪，本次 encounter 固定为未接合，飞船沿底层平路通过，不能在坡中途突然生成支撑或先腾空再等待加载。高速腾空和手工跳跃允许路线游标先跨 tile；运行时在接近时 pin 目标图块，平台飞行期间同时 pin `lastTakeoff.tileToken` 与 `lastTakeoff.landingTileToken`，落地后的 pending gate 继续 pin 同一目标，全部仍受 `maxTiles=3` 约束。空中碰撞候选也显式加入这份目标 token，不能再只从移动中的 current ±1 邻域猜测落地区。若新的 current road 仍在构建，道路池保留上一帧完整呈现并通过 `continuityHeldTokens` 公开该短暂状态。平台飞行的下降接触必须先以世界 X/Z 验证完整飞船占地确实命中当前路、互补支路或对向道路，再提交 `grounded=true`；空隙或道路外仍直接进入坠毁结束。运行时保留首次顶棚/地面接触比例用于诊断与事件，同时只把核心返回的 `endAltitude/endVelocity/endGrounded` 写入权威状态；若顶棚后仍在同帧落地，两项事件按顺序发布。顶棚代理继续使用飞船模块现有的保守 `maximumCoveredTopOffsetM` 加 `0.05m` 接触余量；运行时不会另造一份船体尺寸。只读诊断公开源/目标 token、普通签名、视觉/碰撞/已呈现三项就绪、拦截次数、道路池 pin、continuity hold 及运行时 pinned count。

纵向控制遵循唯一权威链：数字油门命令先进入解析核心，`resolveLongitudinalDynamicsStep(...)` 再把区间平均推进、接地滚阻 `0.24m/s²`、线性阻力 `0.015v`、空气阻力 `0.001_35v²`、`7.5m/s²` 行车制动、地表载荷和坡度合成为一次解析速度积分。新局从真实 `0` 起步；松开 W 会立即把踏板额外推力归零，但贴地1挡、零踏板、未制动且未断扭时，核心单独发布真实怠速蠕行力。干燥平路约 `8km/h` 是力平衡而非速度下限，`16km/h` 起怠速力严格归零；S、换挡、腾空和2/3挡都会完全断开它，因此制动仍能停到精确 `0`，坡度与地表也可让飞船低于8甚至停住。1/2 道路推进级和高速道路/跳台 3 挡在干燥平路满油门分别自然平衡于约 `110 / 160 / 280km/h`，不是硬限速。MT 的 Q/E 只请求相邻挡，目标挡最低速度为 `0 / 70 / 140km/h`，降入 1/2 挡的安全上限为 `125 / 190km/h`；拒绝不改速度，接受后统一断扭 `0.30s` 并让 RPM 回落。2 挡在 `35km/h` 推进归零、到 `70km/h` 才恢复满扭；3 挡在 `90km/h` 归零、到 `140km/h` 恢复满扭，中间均按平方曲线连续恢复。手动挡保留选定挡位但会真实拖挡，低速推进不足以抵消阻力，必须 Q 降挡；自动挡禁用玩家 Q/E，按 `90 / 70km/h` 切换1、2挡，并按 `140 / 120km/h` 切换2、3挡。P 关闭时 M 在 W 手动与无目标速度上限的持续满油门之间切换；P 开启时领航统一调油、滑行和制动，M 只保存退出 P 后的偏好。T 独立切换变速箱权威，不与 P/M 争夺纵向控制。P 的 `120km/h` 普通巡航通常保持2挡；P 关闭后的无上限满油门可由 AT 自动升入3挡。有效护栏、静态障碍和动态障碍撞击分别保留碰撞前纵向速度的 `78% / 58% / 72%`；受保护的重复接触不重复损失速度。运行时只在重置或拾取时以已收集数量 `c` 刷新共享烛光档案，使用 `p=c/(c+18)` 同时得到 `maximumRpm=12_000×(1+0.25p)`、`spoolUpRatePerSecond=2.4×(1+0.50p)` 与飞船颜色进度；零烛光核心为 `1_800–12_000 RPM / 2.4s⁻¹`，成长后分别渐近 `15_000 RPM / 3.6s⁻¹`，松油门后的 RPM 与尾焰 `exhaustEnergyNormalized` 仍按权威余转自然回落，但额外踏板推力不会残留。横向执行器在 `0 / 120 / 160km/h` 的速度/加速度/阻力锚点为 `7/12/2.0`、`9/15/2.2`、`10/17/2.4`，更高速度继续使用末端值；手动与自动共享同一包。速度 FOV 增益也在 `160km/h` 饱和且最多增加 `7.5°`，3 挡不会继续放大镜头。HUD CORE 表、尾焰和声音读取同一核心包；最终净加速度包含全部阻力、坡度、撞击与约束，暂停冻结完整反馈，可见墙钟时间由不超过 `45ms` 的子步完整积分。

T 自动挡在 `90km/h` 执行 `1→2`、在 `70km/h` 执行 `2→1`，并在 `140km/h` 执行 `2→3`、在 `120km/h` 执行 `3→2`；两组 `20km/h` 滞回避免阈值抖动。AT 会把桌面与触控的四个玩家 Q/E 按钮同步设为 `hidden + inert + aria-hidden + disabled`，因此按钮退出布局、焦点和辅助技术；切回 MT 后四项隐藏语义立即撤销，再按当前挡位与换挡状态恢复真实可用性。只有自动调度可在 AT 请求换挡。仪表仍显示 MT/AT、当前挡位、三挡推荐工作带和当前 AT 精确升降挡阈值；3挡以“高速/跳台”标识。AT 高挡低速仍发布真实拖挡或失速，但提示说明系统将自动降至安全挡，不会要求玩家按 Q。每次玩家换挡拒绝只取得 `1_600ms` HUD 展示租约，重复失败刷新租约；展示按单调墙钟过期，因此暂停也不会把红态钉住。到期只清当前拒绝并原子恢复已接合、拖挡、失速或换挡中的真实状态，`lastGearShiftRejectReason` 与计数继续保留为历史诊断。

Film 的远置镜头与普通驾驶镜头共用同一场景驻留合同，呈现驻留不得再以飞船浮动原点作为相机位置的替代。摄影机远裁面扩展到 `1_600m`；地貌在本帧摄影机提交后读取真实绝对 X/Z、FOV、宽高比、朝向和有效雾远面，选择与真实地面视锥相交的 `96m` 单元，并在外侧保留两格卸载滞后。移动/桌面池固定预分配 `1_280 / 2_048` 格，覆盖 `2.4:1 / 32:9`、Film `84°` 与六境 `720–1_200m` 基础雾距；选择、哈希和实例更新不逐帧分配。更极端的视口仍按实际视锥计算，若固定池不足则记录超限并收近纯呈现雾，不能静默露出空地。每帧顺序固定为先提交摄影机，再更新地貌、道路图块、裁切与光照，所以 Film 硬切不会暴露上一机位的一帧空洞。该合同只管理视觉驻留与诊断，不扩大碰撞、实体生成、地图路线或玩法权威。

`hood-collision-guide-v3` 只复用飞船模块真实伤害 `playerHalf/colliderHalf`，把半尺寸 `0.72 / 0.58 / 1.36m` 加倍为固定 `1.44 × 1.16 × 2.72m`；可见船体几何、缩放、材质或包围盒不得重定义尺寸。运行时沿已提交而非候选的 `PathPlan` 计算等尺寸前向投影，但只向呈现层输出四个短角标和两条下侧导轨；完整后截面、纵深盒、远端扫掠门、中心轴、中央标签与两处标距不再属于玩家界面。角标内部和驾驶消失点必须保持透明；桌面只在视口下缘发布真实宽度读数，移动端不发布可见读数。威胁预测是已提交路线上的只读有界探针：它复制权威运动快照，在有限 `2.5s` 警戒窗和固定迭代/采样预算内前推碰撞包络；若窗内遇到跳台 lip，则纳入由该 lip 导出的未来离地段，若飞船已经腾空，则从当前活动腾空状态继续，同时逐段检查路线地面和顶棚包络。只有同一已提交走廊中的障碍或表面与伤害碰撞体在横向、高度和时间上重叠，才按 TTC 在 `2.5s / 1.2s` 分别进入静态琥珀警戒和静态红色危险。该 HUD 探针不得调用长跨度、高密度物理扫掠，不消费地图最近距离，也不得把预测状态回写为真实起跳、腾空、着陆或碰撞。运行时在最终车头相机提交后、呈现前恰好更新一次；路线基、探针、地面/顶棚采样、腾空推演或投影无效时安全降为常态或整组关闭，任何无效结果都不得钳到屏幕边缘。该层没有动画，只读路线、碰撞尺寸、权威运动快照和碰撞候选，不能写速度、路线、生命、横向位置、姿态、碰撞、控制或任何玩法与物理状态。

HUD 运行时只更新结构化控件中的状态子节点，不覆盖按钮原有图标、名称或键帽；视觉、可访问名称、`aria-pressed` 与 `data-*` 必须由同一状态同步函数发布。自动驾驶指令包在最多 `10Hz` 的非 live 边界同时投影意图、横向权威、独立纵向权威、制动原因、最近障碍距离/TTC 及连续风险；`clear / guarded / elevated / critical` 使用非对称进入/退出阈值防止闪烁，障碍/边界/弯道制动分别提供最低真实风险。只有权威或制动模式的离散变化进入唯一 polite 状态节点，百分比和 TTC 不逐帧朗读。速度指针、横向位置圆点和输入反馈逐帧更新；横向圆点使用权威 `state.lateral / safeHalf` 归一化到轨道 `4–96%`，可访问 `-100…100` 数值及“左/居中/右”文本最多 `10Hz` 更新。分数、距离、生命、操控和其他领航文字同样最多 `10Hz`，天气时间线最多 `4Hz`，FPS 继续复用每秒一次的渲染审计。人工天气只有显式 `manualTest=1` 才启用并显示。

移动驾驶舱由 `shouldUseMobileCockpit()` 统一判定：`≤920px` 宽或 `≤560px` 矮横屏直接启用；其余设备只有在 `navigator.maxTouchPoints > 0` 或任一粗指针成立，且长边 `≤1_366px`、短边 `≤1_200px` 时启用。触控能力优先于同时存在的精细指针，因此连接 Magic Keyboard 不会让 iPad 退回桌面。手机使用独立于桌面双翼的 glance、航路/警示槽和移动操作坞：速度、得分、烛光和生命复用原权威格式化结果，下一指令与距离平时占用唯一航路槽，限速或安全制动出现时按优先级在同一位置替换普通航路文案；领航、自动油门、视角和暂停始终可达。移动专用自动驾驶状态胶囊只在 P 领航开启时投影意图、稳定风险和真实制动；P 关闭时必须通过真实 `hidden + inert + aria-hidden` 移出视觉、可访问性和布局，P 关闭时 M 满油门单独开启只更新其独立状态，不能让胶囊复现；P 开启后 M 仍可切换保存偏好，但按钮显示领航接管并且不能争夺纵向权威。双轴 `≥700px` 的 iPad 仍只在 P 开启时显示完整指令面板。手机竖屏与矮横屏拥有独立呈现几何，而不是把桌面或竖屏结构压缩跨列；仪表和地图详情默认折叠，短边 `<700px` 时打开一侧会原子关闭另一侧，iPad 保留两侧独立选择。切回桌面不清除已选择的移动折叠状态。

`syncMobileCockpitPresentation()` 只同步桌面/移动外壳所有权、`data-mobile-cockpit / data-mobile-expanded`、两个真正 disclosure 的 `aria-expanded` 与详情的 `hidden / inert / aria-hidden`；领航按钮只用 `aria-pressed`。工具抽屉打开时原子关闭两块详情并让 glance 退出命中/可访问树；iPad 缩到短边 `<700px` 时只保留 `lastExpandedSection` 指向的最后一块详情。移动自动驾驶胶囊的可见条件严格等于“移动驾驶舱启用且 P 领航开启”。`measureViewportPresentation()` 测量 app、visual viewport 与正 DPR，所有窗口、方向、visual-viewport、app `ResizeObserver` 和 DPR 变化经一个 RAF 合并到 `commitViewportPresentation()`；CSS 变量、相机、Renderer、后处理、HUD 与地图共享同一快照。只有 app 尺寸或有效 DPR 真变化时才重建 WebGL 缓冲，单纯 visual-viewport 偏移只更新 CSS，不能造成连续缓冲重建。隐藏 Canvas 保留上一张完整地图，展开后在下一 RAF 重测。

移动交互呈现另遵循统一边界：原生文本选择、拖拽和长按菜单只在活动飞行层禁用，作用域限于 Canvas、实时 HUD、详情抽屉和五个驾驶键；开始、暂停、结算、飞行手册及其他模态仍保留可选文本和原生长按菜单。常规手机横屏五键保持 `52–60px`；`568×320 / 640×360` 使用左侧单排五个 `44px` 键、右侧完整换挡范围槽和独立详情列。HUD、自动领航胶囊、任一详情、换挡器与驾驶键必须完整位于四向安全区内并互不覆盖。`visualViewport`、窗口尺寸或方向变化只触发呈现重排，不能改写速度、路线、控制、生命或本局状态。

生命与烛光成长必须从权威状态经过两个独立投影函数。`updateLifeMeter()` 将 `3 / 2 / 1 / 0` 映射为 `healthy / wounded / critical / depleted`，只写固定三个 `data-life-slot/data-life-active`、`data-life-count` 和 `data-life-state`；三段完整度轨由父级生命状态纯 CSS 投影。`updateHandlingMeter()` 保留 `base / responsive / agile / elite`，只写 `data-handling-level`、六位小数的连续 `data-handling-progress`、移动烛光轨的 `--mobile-candle-progress` 与烛光计数；这些值仅服务呈现，不形成第二份玩法状态。两函数不得互调，任一函数的源码都不得写另一组 DOM、data 状态或 CSS 变量；样式层的 `--life-*` 与 `--candle-*` 同样隔离。

普通障碍和护栏接触只可调用 `takeDamage()`；该 fail-closed 入口是普通伤害、扣血和受击副作用的唯一运行时权威。它先用 `canAcceptOrdinaryDamage(...)` 检查 `1.32s` 活动玩法无敌与本渲染帧锁；接受后必须在事件、音效、实体和 HUD 之前原子开启两道保护，再只扣一命。渲染帧锁每个 `animate` 帧只重置一次，因此同一帧的多个玩法子步最多接受一次损伤；`advanceDamageInvulnerability(...)` 只消费运行中、未暂停、未结算的玩法时间，暂停与页面隐藏均冻结倒计时。被保护的接触只计只读拒绝诊断，不得触发生命、事件、声音、实体或 HUD 变化。每次有效命中恰好提交一次 `0.48s` 强边缘冲击和生命卡反馈、一次 `aria-live="assertive" aria-atomic="true"` 播报，并在完整无敌期显示稳定护盾；船体不得以透明度闪烁表达保护。`updateDamageProtectionPresentation()` 把同一 `state.invincibleTimer`、总时长、视角、暂停和减少动态状态交给飞船模块，不再假设护盾是单个 Mesh；车头只设置中心透明碰撞括线的保护状态，俯视由飞船模块复用方向环。桌面、移动与车头进度均消费同一个只读比例，静默的十分之一秒显示不得创建新播报。

HUD Liquid Glass 在 `updateZone → updateCamera → updatePhysicalLighting → updateSurfaceWeather → updateDecoration` 完成后最多每 `100ms` 分析一次。信号使用雷闪混入前的天气天空、雾、道路材质，以及本帧曝光、环境光、太阳强度/方位、隧道灯和包围度，通过与 High 管线一致的 ACES 公式估算 `left / right / position / compass / input` 五区显示亮度；禁止 `readPixels`、`readRenderTargetPixels` 或 `getImageData`。根和五个逻辑区各自持久保存 `mode / candidateMode / candidateSince / lastSwitchAt / switchCount`，两个输入宿主共享一个 `input` 状态，其余区不得借用根或邻区的时钟。亮场使用约 `140ms` attack 增加表面透明度与阴影，暗场使用约 `520ms` release 恢复通透；每个状态独立执行 `0.32 / 0.42` 双阈值、`240ms` 候选驻留与 `600ms` 最短切换。连续材质以 `surface=0.55+0.25L`、`strong=0.64+0.24L`、`control=0.50+0.26L` 为基础；亮/暗模式分别施加 `+0.05/+0.02/+0.06` 与 `-0.03/-0.03/-0.02` 的局部安全偏移，边缘反向变化，高光约为 `0.015–0.030`。左侧同级遥测统一使用运行时 `cell` 深度；样式层只为没有公共包络的独立文字承载板提供 `0.90 / 0.88`，不能提高整块大壳或单个遥测卡到近乎不透明。量化后才写局部 `--hud-glass-*` 变量及 `data-hud-contrast`，相同签名不重复写样式。该层只改变呈现材质，不重着色语义状态，也不写速度、路线、碰撞或控制权威；诊断逐区发布完整状态时钟、采样序号、亮度、目标、surface/strong/control/cell/edge/highlight/shadow、反射颜色/位置和签名。

运行时把 `window.NeonI18n` 作为动态界面的必需依赖。语言、道路族、路线类型、出口、天气、画质与运行状态始终保留语义编号或枚举；只有写入 DOM、ARIA 或 Canvas 时才通过稳定键或 `translateSource()` 生成文案，并由 `formatNumber()` 统一处理数字及米、公里/小时、帧/秒单位。语言通知会在不调用切换器、不重置路线且不改玩法状态的前提下，同步刷新启航、暂停、结算、声音、曲库、天气、画质、HUD、视角、领航、输入与触控可访问名称，失效纯呈现缓存，并请求下一帧原子重绘地图。内部 `edge.family` 必须先映射为道路名称，不得直接泄漏；旧 Canvas 标记也必须经过翻译并使用最大文字宽度。语言入口不属于 HUD，卸载时必须解除运行时订阅。

战术导航外壳由主运行时统一提交模式、朝向、威胁等级、指令、目标出口、距分流、刹车状态、可访问路线摘要与航向。只有双 Canvas 已成功交换完整画面后，`commitMinimapPresentation()` 才从同一导航载荷更新这些 DOM 字段；失败帧保留上一组画面与文字，实时可见罗盘指针仍逐帧转动，但地图拥有的无障碍航向会等待同一次成功提交。道路细节的可见标题显示实时四舍五入距离；状态播报按 `<100m / 100–199m / 200–499m / ≥500m` 分别量化到 `10m / 25m / 50m / 100m`，减少无意义的逐帧朗读。

Read-only diagnostics publish contract version/mode, hidden clusters, query/reuse counts, minimum gap, extra draw groups, and allocation ownership.

## 地下隧道地貌裁切 / Underground terrain cutout

运行时为基础与 High 地貌材质安装同一绝对世界坐标着色器边界。每帧更新相机后，它只沿当前已提交路线预采样后方 `36m` 至前方 `156m` 的 `16 × 12m` 路段；只有地下隧道帧获得非零半径，两端在洞门外归零。第 2 版裁切合同删除了会挖到罩体外侧的固定 `8.2m` 下限，半径严格由实时道路半宽、`0.49m` 墙中心、`0.54m` 墙厚与 `0.18m` 内墙重叠推导；标准环道为 `5.60m`。这会清除地面起伏及合并进地貌几何的岩石/植被，同时把切口藏在实体墙内并保留 `0.36m` 外墙厚度，不再从高/斜视角露出罩外空环。所有帧与 uniform 数组均预分配，画质切换不改变裁切，额外绘制组为 `0`；诊断只读发布合同、激活状态、段数和最大半径。

Runtime installs the same absolute-world shader boundary on base and High terrain. After the camera updates each frame, it pre-samples `16 × 12m` segments of the committed route from `36m` behind to `156m` ahead; only underground-tunnel frames receive a nonzero radius, with endpoints tapering to zero outside portals. Version 2 removes the fixed `8.2m` minimum that excavated beyond the enclosure. Radius is derived only from live road half-width, the `0.49m` wall centre, `0.54m` wall thickness, and `0.18m` inner-wall overlap; a standard loop resolves to `5.60m`. This removes relief plus rocks/vegetation while keeping the cut inside the solid wall with `0.36m` of outer wall remaining, so high or oblique cameras no longer expose an exterior halo. Frames and uniform arrays are preallocated, quality changes cannot disable the cutout, and the change adds `0` draw groups; read-only diagnostics expose the contract, active state, segment count, and maximum radius.

## 天气能见度与高视角编排 / Weather visibility and high-view orchestration

运行时每帧先通过 `OPEN_AIR_VISIBILITY_CONTRACT` 将配置可见度与雾/尘消光合成，再以隧道暴露量连续归一；户外强雾的近雾上限从 `18m` 收紧到 `4m`，完全封闭处仍恢复中性清晰大气。Top 相机与向上射线同时接受 `WEATHER_VIEW_VOLUME_CONTRACT` 的 `26m / 14° / 72m` 边界检查，云层还必须满足 `36m` 桥面净空和 `45m` 最低云底。只读诊断发布这些能见度、相机包络和复用预算；运行时不会借此改写天气时序、物理、路线或控制权威。

Each frame, runtime first uses `OPEN_AIR_VISIBILITY_CONTRACT` to compound authored visibility with fog/dust extinction, then normalizes that result continuously through tunnel exposure. Dense outdoor near fog is capped at `4m` instead of `18m`, while a fully enclosed route still restores neutral clear air. The Top camera and upward view ray are checked against the `26m / 14° / 72m` bounds of `WEATHER_VIEW_VOLUME_CONTRACT`; clouds must also retain `36m` of deck clearance and a `45m` minimum bottom. Read-only diagnostics publish the visibility, camera-envelope, and reuse budgets, without granting runtime any new weather-timing, physics, routing, or control authority.

## 跳台腾空、真实道路落地与坠毁 / Platform flight, physical-road landing, and crash

普通结构纵坡继续由路面接触权威承载，所有垂直运动使用标准重力 `9.81m/s²`。玩家的手工与触控起飞可在平路、结构纵坡和实体跳台承载面通过 `launchVertical('space')`；垂直初速保留 `speed × grade / hypot(1, grade)` 坡面切向分量，再叠加由 `4.6m` 目标高度反算并以 `1 / hypot(1, grade)` 投影到世界 Y 轴的主动冲量。这使高速上坡在首个垂直扫掠帧真正分离；主动飞行清除 `jumpPlatformFlightActive`、保留当前路线 `±safeHalf` 护栏且不获得跨路落地权限，领航避障在坡面仍禁止伪造 SPACE 冲量。只有未触发主动起飞且扫过实体跳台坡唇才进入 `jump-platform-release`：离坡速度严格为 `speed × grade / hypot(1, grade)`，预计腾空时间由同一速度与重力计算，实际时间由 `state.airTime` 连续累计，不存在隐藏弹射冲量。只有平台坡唇自然飞行才跳过当前道路 `±safeHalf` 护栏，并受有限世界横移包络约束。下降接触在提交 `grounded=true` 前，将精确接触分数转换为世界 X/Z，并查询当前可见真实道路带。当前路命中保持计划；互补岔路命中提交对应 movement；对向命中先采用目的图块完整 `1,080m` 的反向代理，然后在约 `5.76km` 回主路边内完成局部立交：`1,080–1,800m` 抬升、`1,440–2,160m` 横移、`1,800–2,040m` 平台、`2,040–2,760m` 落回地面，余段保持普通主路。运行时把新 `PathPlan`、前后游标、局部横向与路线选择作为同一事务提交，原位接管已可见的对向障碍和烛光；落地后护栏重新以新道路中心 `0` 计算，不再用永久世界横移带夹住飞船，渲染原点与小地图同时失效重算。命中两路之间的空隙、没有有效后继的道路或全部道路之外时，直接发布 `off-road-crash` 并进入唯一 `endGame()` 边界，不扣一条生命后复活。顶棚仍由原 `sweptVerticalContact()` 优先处理。

Ordinary structural grades remain under surface-contact authority, while every vertical trajectory uses standard `9.81m/s²` gravity. Player SPACE or touch launch may call `launchVertical('space')` from flat pavement, a structural grade, or a supported platform plane. Initial vertical velocity preserves `speed × grade / hypot(1, grade)` and adds the `4.6m`-derived active impulse projected onto world Y by `1 / hypot(1, grade)`, so an uphill support separates on the first sweep. Deliberate flight clears `jumpPlatformFlightActive`, retains the current-route `±safeHalf` guardrail, and receives no cross-road landing authority; Autopilot still cannot manufacture SPACE on a passive grade. Only a physical platform lip swept without a prior deliberate launch enters `jump-platform-release`. Its vertical velocity is exactly `speed × grade / hypot(1, grade)`; the same velocity and gravity derive predicted airtime while `state.airTime` accumulates the measured duration, with no hidden launch impulse. Only natural platform flight bypasses the selected road's `±safeHalf` guardrail within a finite world-lateral envelope. Before committing `grounded=true`, descent contact converts the exact swept fraction to world X/Z and queries the visible physical road ribbons. A current-plan hit retains the route, a complementary-fork hit commits that movement, and an opposing hit first adopts the destination tile's complete `1,080m` reverse proxy. The approximately `5.76km` return edge then performs one local interchange: rise over `1,080–1,800m`, shift laterally over `1,440–2,160m`, hold the crest over `1,800–2,040m`, descend over `2,040–2,760m`, and continue as an ordinary main road. Runtime commits the new `PathPlan`, previous/current cursors, local lateral, and route choices as one transaction and assumes authority over the already visible opposing hazards and candlelights in place. The grounded guardrail is then centered at local `0` instead of permanently trapping the craft inside a world-offset band, while render origin and minimap are invalidated together. Contact in the inter-road gap, on pavement without a valid successor, or outside every road emits `off-road-crash` and enters the sole `endGame()` boundary immediately instead of consuming one life and respawning. Ceiling priority remains owned by the existing `sweptVerticalContact()` solver.

## 整局遥测与冻结结算 / Run-wide telemetry and frozen debrief

运行时在每次物理落地或路外坠毁时只提交一次飞行结果，分别累计全部、成功、跳台、成功跳台腾空秒数以及最长单次，并单独记录跳台起飞/安全落地。每次通过统一保护闸并真正扣除生命后，`damageCount` 恰好增加一次；其中护栏来源再增加一次 `guardrailDamageCount` 子类计数，普通障碍次数由总数减去该子类得到。无敌期或同一渲染帧内被拒绝的接触只进入拒绝诊断，不得改变任一评级计数。仅 `modelDebug` 可见的 `acceptGuardrailDamageForLayoutAudit()` 也只能调用真实 `takeCurveGuardrailDamage()`，不能清除保护计时、释放帧锁、直接写计数或强制结束，用于浏览器端连续验证同一生产边界。最高速度在每个有界玩法步从权威 `state.speed` 更新；平均速度由纯评级核根据距离与 `gameplayElapsedSeconds` 推导。若有效扣血在空中结束本局，当前未完成腾空会进入总量和最长事实，但不会进入成功腾空。路外坠毁先提交失败腾空，再调用 `endGame()`，防止漏计或双计。

`endGame()` 在展示共享 overlay 前只创建一次深冻结 `flightRatingSnapshot`；语言切换只调用 `renderFlightDebrief(snapshot)` 重绘文案，不重新采样状态。五边形投影也只读取该快照，并严格按 `safety → pace → endurance → collection → airborne` 映射五个原始 `0–100` 分，不根据图形面积重算加权总评。缺样本或非有限分数保持未解析，使折线在对应轴断开且取消填充，不能回填为 `0`；逐项 meter 与原始证据仍是权威明细。新局同时清空快照和全部累计器。空中落地查询把当前 `PathPlan` 与活动图块令牌一并交给路网，避免互斥的预热 recovery 变体被误认为真实道路。诊断只读发布累计量、最高速度、总扣血、障碍派生数、护栏子类数和冻结评级。

Runtime commits each physical landing or off-road crash exactly once, separately accumulating all, successful, platform, and successful-platform airtime plus the longest flight and platform takeoff/safe-landing counts. Every contact that passes the shared protection gate and actually removes a life increments `damageCount` exactly once; a guardrail source additionally increments the `guardrailDamageCount` subset, while obstacle damage is derived as their difference. Invulnerable or same-render-frame rejected contacts enter rejection diagnostics only and cannot change either rating counter. The model-debug-only `acceptGuardrailDamageForLayoutAudit()` may call only the real `takeCurveGuardrailDamage()` authority; it cannot clear protection, release the frame latch, write counters, or force game over, allowing browser audits to exercise the same production boundary repeatedly. Maximum speed samples authoritative `state.speed` after every bounded gameplay step, and the pure rating core derives average speed from distance and `gameplayElapsedSeconds`. If accepted damage ends a run in mid-air, the unresolved interval enters total and longest facts but not successful airtime. An off-road crash commits its failed flight before calling `endGame()`, preventing omissions and double counting.

`endGame()` creates one deeply frozen `flightRatingSnapshot` before exposing the shared overlay. Language changes only call `renderFlightDebrief(snapshot)` and never resample gameplay. The pentagon projection also reads only that snapshot, mapping the five raw `0–100` scores in strict `safety → pace → endurance → collection → airborne` order without recomputing the weighted overall rating from shape area. A missing sample or non-finite score stays unresolved, breaks the outline on that axis, and disables fill instead of being coerced to `0`; the per-dimension meters and raw evidence remain authoritative. A new run clears the snapshot and every accumulator. Airborne landing queries pass the committed `PathPlan` together with active tile tokens so mutually exclusive warmed recovery variants cannot masquerade as physical pavement. Read-only diagnostics publish total, obstacle-derived, and guardrail damage evidence beside the remaining accumulators, maximum speed, and frozen report.

The final tablet presentation breakpoint owns iPad geometry: the five sustained driving controls measure `80–88px`; the four direct actions, utility toggle, and utility-drawer actions measure `56–60px`; landscape uses one action row and portrait retains `2 × 2`. Compact `900–1023px` landscape keeps the fixed `64px` route/advisory slot below the head so the five-cell utility drawer has its own lane; only `1024px+` landscape shares the safe-area top line between both wings. Opening utilities, switching short or long Chinese/English copy, updating distance, and replacing guidance with a speed limit cannot move or resize the slot. `commitMobileRouteText()` writes only changed strings, reducing layout invalidation without caching or creating route facts.
