# Navigation / 路线与导航

## 中文

`getTextureRevision()` 提供 O(1) 的导航纹理身份发布序号，供渲染器在首次绘制前同步 High 纹理过滤。完整图块成功注册时递增，已注册视觉的出口图集实际切换材质/纹理身份时再次递增；不能用 GPU 纹理总数代替，因为等量释放和新建可保持总数不变。每个视觉保留不随恢复路线变化的发布租约，未注册、构建失败、被替换或池已处置时的回调无效；图集释放同时断开语言订阅并清空回调。纯几何变体安装/激活、相同 resident 复用、同一语言图集复用、画质切换及外部 HDR 内容版本更新均不递增。

持续负载保留原有 Low/Medium/High 材质分级、全部结构模型、阴影及 `19` 个预建批次。Film 的结构圆柱是绝对世界坐标，只在图块显隐切换时整池恢复/隐藏；变体发布继续由对应 layout 写入器同步新矩阵与可见性，玩家原点移动不再每帧重复遍历数千条记录。环境交通每次写入当帧实例矩阵后复用 Three 的 `computeBoundingSphere()` 更新完整包围球，包含几何中心偏移、非均匀缩放和当前实际提交数量；由主视角及阴影各自的视锥裁剪该批次，禁止因主视角不可见而修改对象 `visible`。诊断公开 `routeCameraBlockerVisibilitySweepCount / ambientTrafficBoundsUpdateCount / ambientTrafficFrustumCulling`；回归验证所有提交顶点均在当帧包围球内，转头重现以及主视角外仍在光源视锥内的投影物均保持正确。

局部遮蔽会读取同一场景光照 rig 的稳定全局透射 uniform，只补足室外光尚未受到的衰减。深洞已有的全局暗化不会再叠乘一次，避免 Low/Medium 缺少近距聚光时过暗；没有光照 rig 的独立构建使用室外透射 `1`，必须先创建 rig 再创建道路池才能共享实时比例。

隧道静态光改走 Three 的间接漫反射路径，由真实反照率、顶点颜色、车辙/石材细节和 AO 调制；`PI / 0.18` 以固定 18% 参考灰把旧的出射辐亮度标量换算为入射照度，保住灯池之间的基础亮度；不会除以真实材质反照率，因此仍保留明暗纹理差异，基础材质与着色器都不再额外自发光。新增 `tunnelEnclosure` 只按作者隧道范围和洞口渐变生成，与玩家、镜头、灯站亮度无关；道路内表面、隧道内皮和肋架/灯壳分别携带，普通桥梁与壳体外皮保持室外值。它仅衰减方向光和室外 ambient/IBL（深部剩余分别为 `2.5% / 14%`），真实局部聚光及其阴影、静态基础照明不受该遮蔽衰减。道路与恢复变体的属性合并仍按预算分块，新增数据不改变原位置、颜色、法线、照度或索引缓冲，也不增加 Mesh、Light 或 draw group。

道路装配切片：桥墩、柱冠、隧道规格、横梁与灯具分别归还调度器；连续隧道壳体的曲率细化、顶点、索引、法线和包围球按小段生成。`createBuildJob.step(budgetMs)` 在剩余预算内批量推进隧道微步骤，阶段变化或达到 `4_096` 次安全上限即归还，避免每行占用一次 idle 回调。法线保留 Three r160 的逐三角 Float32 写回顺序；道路位置、灯光照度、接缝和绘制批次数不变。未完成的构建不会加入场景，取消/失败释放私有几何、材质、纹理和图集租约，共享道路模板由外层归还；完成后由 `visual.dispose()` 接管。预算属于协作式目标，其他装配阶段、GC 和 GPU 首次上传仍需单独观测。

长航程 CPU 路网采用显式所有权回收：运行时只租住当前前一图块、当前图块、向前 3 个预热图块，以及仍由 Film、落地握手、道路 resident、候选 PathPlan 或离线船流引用的 token。`pruneRuntimeTopology()` 按 token 级联删除 node、edge、movement、恢复拓扑、恢复分流和双向选择缓存；一个恢复源只额外保留紧邻目的图块，不能递归保留整条未来链。`compactItineraryPlan()` 同步移除不可达前缀并重建 edge 索引与累计长度。路线历史使用固定 `32` 位十六进制的 128-bit 确定性摘要，图块 token 在 JavaScript 安全整数索引范围内最多 `55` 字符，不再随航程线性增长。诊断分别发布当前/峰值注册量、token 字符数、回收量，以及可见道路和净空查询实际扫描候选数。

空中落地的纵向占地以真实铺装并集为权威，而不是要求完整船长只能装进单条 edge：同路线族的相邻 edge 只有在端点位置误差不超过 `0.03m`、高度误差不超过 `0.12m`、朝向误差不超过 `0.5°` 且两侧都容纳完整船宽时才能共同承托。这样无缝主路的内部 edge 边界不会再形成约 `2.72m` 的假路外带；未激活图块、暖备变体、不支持道路、空间交叉和真实道路尽头仍不能补出幽灵路面。查询结果以 `single-edge / connected-road-seam` 公开支撑来源；同高重叠路面的空间分数仅在超过 `0.000001` 的归一化差值时才能改选更近道路，否则按当前计划、可选支路、对向回程的顺序保留路线权威。

保存道路图、苜蓿叶结构、图块池和路线图。道路采样与地图共享路线合同，地图不得生成第二套玩法坐标。

道路 metadata 使用当前可达速度包络：主路/直行发布 `45m/s`，collector 为 `36m/s`，右转 direct ramp 为 `32m/s`，loop ramp 为 `25m/s`。这些是路线级建议值；运行时仍根据真实曲率、`5.5m/s²` 横向加速度合同和 `7.5m/s²` 行车制动计算更严格的即时限速与停车距离。

`TrackGraph → PathPlan / routeCursor → DecisionGuidance` 是 Canvas 路网和外层 DOM 模式、方向、威胁、出口、距离与制动信息的唯一权威链。Canvas 完成可见帧交换后，运行时才能提交对应 DOM 与 `data-map-mode`；失败帧不得让文字、状态或地图来自不同的时刻。

地图会事务式分配 world/frame 缓冲，先在私有帧完成全部地形、道路、路线、实体、比例尺和方向图层，再复制到隐藏的 standby Canvas；复制成功后才切换唯一 `.is-presented` 表面。分配、绘制或复制失败不会清空、缩放或隐藏当前 active Canvas，并由运行时进行有界重试。`local`/`road-detail` 保持航向朝上，`overview`/`guided` 保持北向朝上；所有投影继续使用等比例世界 X/Z 尺度。

Canvas 不绘制持久图例；已选/候选路线、障碍、烛光和环境船流由外层 DOM 图例说明。成功交换后，运行时才提交匹配的模式、朝向、威胁、指令、路线状态与无障碍航向；道路细节播报使用分级距离桶避免逐帧噪声。诊断区分尝试帧与已呈现帧，并公开 active 表面、交换/尺寸/失败计数、已提交导航载荷及最近失败阶段。

界面语言只在呈现时解析：Canvas 每帧从语言目录取得方位、出口名、比例尺与距离单位，缓存的 `TrackGraph`、`PathPlan` 和分类结果保持语言中立。三维 2A/2B 路牌以同一冻结出口编号、方向和物理距离生成对应语言纹理；切换时只替换共享图集材质并释放旧引用，不重建道路几何、图块或玩法路线。

桌面 `road-detail` 先按 `0.60–0.72px/m` 的同一 X/Z 比例尺求解，再从 Canvas 可用半高扣除完整玩家箭头和 `1px` 安全边距，必要时收短前视，禁止把玩家标记夹在边缘伪装可见。`overview/guided` 对桌面小面板应用战术比例尺下限，使比例尺标记不超过 `200m`；`291×163` 合同要求前方约 `251.7m`、至少两条 `100m` 刻度且玩家未夹紧。

桌面外置罗盘与 Canvas 内置罗盘始终只有一个方向所有者。高桌面外置仪表位于右下安全区；中等高度桌面把同一仪表缩至约 `112–115px × 140–143px` 并移入左侧安全舱，运行时诊断按实际布局发布位置与边距。紧凑/移动端隐藏外置仪表，只保留地图内罗盘。

道路/桥梁生成器为同一套暖灰 edge shell 预建三档介电路面：Low 不安装坐标 shader，也不采样 normal/roughness 贴图，以最低成本保留 PhysicalMaterial、天气湿润和 LineSegments 标线；Medium 使用不采样 High 贴图的 `standard-road-coordinate` shader，以真实 `roadCoord` 生成 `45m` 接缝、轮迹、路肩压暗、宏观粗糙度和距离衰减；High 再加入程序化 normal/roughness 贴图、细尺度坐标微表面与同源 PBR ribbon 标线。顶面及箱梁侧面采用受控的偏暗暖灰，雾中仍能分开桥面、腹板与梁底，不再形成近白色大板。全部画质沿真实 edge station 保留双侧世界固定参照：`4m` 标记、`5.2m` 空隙、`9.2m` 周期、距物理边缘 `0.45m`；`paired=true`、`worldFixed=true`、`affectsGameplay=false`。切档只交换预建材质和标线可见层，不重建 edge，也不修改碰撞或 `PathPlan`。

生产 split/merge 不再创建或合入 apron/lens；每条 route edge shell 由 `sampleEdge()` 采样、独立封闭并直接合批，是交汇区唯一可见顶面权威，遗留 apron/lens helper 只供离线几何审计。direct 与 loop 在分流后、合流前共享同高、零纵坡、零横倾喉部：direct 为 `164m / 164m`，loop 为 `164m / 136m`，后者覆盖实际 `119.25m` 全宽重叠并让完整洞门保持在同层直段；喉部之后分别用 `120m` C2 过渡进入真实横倾。核心尺寸为 `collectorLength=354m`、`collectorOffset=240m`、`directRadius=400m`；下层 collector 使用 `grade-limited-c2` 剖面，上层 loop 的 flyover 平台高 `13.5m`，全部纵坡不超过 `6%`。

道路净空查询对桥墩与基础要求 `verticalEnvelope={minY,maxY}`，只有水平足迹和道路板竖向区间同时相交才算阻挡；倾斜道路板沿世界竖直线的底面为 `frame.y - deckThickness / abs(frame.upY)`，柱顶与盖梁按这一精确高度接合。桥墩可见轴身半径为 `0.92m`，道路规划与每个 `2.2×1.05m` 基础仍按 `1.24m` 净空半径查询，因此加粗柱体不会缩小既有安全包络。普通单柱的盖梁继续只向最近承重点单侧传力并限制外悬；v5 对向回主路桥声明 `continuous-box-girder`，支点按 `88m` 节奏规划，structural-detail 批次沿真实高架覆盖区加入 `24m` 分段、两侧 `0.34m × 0.72m` 腹板和 `0.20m` 支点横隔，不新增逐跨 Object3D。全量审计仍逐实例读取柱、盖梁与基础矩阵并验证地貌落脚、顶接、偏心、净空与穿模。

旧的整路固定起飞剖面已从 recovery 基路删除；`track.js` 按图块稳定哈希发布一座宽、高、长和横向位置可变的独立实体跳台。四种物理楔体的“长×宽×高”为 `18×7.2×5.2m`、`24×9.4×6.8m`、`30×12.2×8.3m` 与 `36×10.6×9.8m`。正常 3 挡以 `260km/h`、标准重力 `9.81m/s²` 审计，真实坡唇产生约 `4.32–4.34s` 腾空；共享横移合同在 `30 / 60 / 120Hz` 均能抵达对向道路 `-24m` 中心，最小余量超过 `2.22m`，不存在隐藏弹射冲量。`queryAirborneLandingSupport()` 只扫描活跃图块的真实道路带及显式 `opposing-intertile`，并把命中区分为当前计划、可选互补岔路、对向回程或不支持。对向命中由 `resolveAirborneLandingRoute()` 精确映射到完整 `0–1,080m`、全半宽 `8.4m` 的同几何反向代理，再进入约 `5.76km` 的 `opposing-crossover-profile-v5-local-merge`：`1,080–1,800m` 抬升至世界高度 `20m`，`1,440–2,160m` 用 `720m` C2 S 形完成 `24m` 横移，`1,800–2,040m` 为 `240m` 平台，`2,040–2,760m` 下降，随后以普通主路姿态进入下一 approach。半宽在 `1,080–1,200m` 由 `8.4m` 收至 `5.6m`，保持至 `2,640m`，再于 `2,640–2,760m` 放宽回 `8.4m`。真实 `280km/h` 审计的横向、竖向、三维法向峰值约为 `0.1295g / 0.1023g / 0.1650g`，最大纵坡约 `5.63%`，横倾不超过 `8°`。该桥使用 `88m` 支点节奏的连续箱梁合同；直道岔路继续使用内侧 `2m`、外侧 `18m` 的非对称 C2 剖面，并分别与对向路及另一支路保留 `7.2m` 铺装净空。

山体廊道顶棚与地下隧道 U 形侧墙/顶棚使用同一套连续 indexed `BufferGeometry`；纵向 station 间距 `≤2m`、弦误差 `≤0.005m`，portal、rib 与道路壳体真实 station 精确并入共享 shell 行。地下环道在受保护壳体内降到 `-1m` 结构盆地；地下罩以道路肩部 `0.22m` 外沿为零缝接点，墙中心/厚度为 `0.49m / 0.54m`，屋顶外扩/厚度为 `0.84m / 0.46m`，因此墙只向外生长且在墙外保留 `0.08m` 顶板搭接。道路与墙脚共享真实 BufferGeometry 折线，最大缝隙与侵入均为 `0`；地下门框离道路接点保留 `0.02m`，不会切入路壳。深 `2.4m` 的洞门框在交汇喉部外退让 `12m`；完整屋顶对上层道路的最小净空为 `0.608719m`，全部 `16` 个洞门对 sibling 路壳的最小间隙为 `1.546623m`，均高于 `0.25m`。立交视觉沿每条隧道路线独立密排灯罩/扩散片，并让整段每一个灯具外观保持可见发亮；只有这些灯具表面可以自发光，顶棚梁、连续 shell、侧墙和道路不得自发光。每个灯具还发布带 tile token、edge、profile 与 station 身份的冻结 authored emitter，供渲染层精确绑定真实局部光；导航层不生成相机或玩家相对的兜底 emitter，普通开放桥底灯合同与隧道 emitter 分离。视觉 shell 不拥有碰撞：玩法/运行时沿整帧路线和弹道扫掠 `sampleEdge()` 的道路与顶棚边界，约束帧末状态，防止高速飞船穿过上方道路或有顶结构。

`sampleEdge()` 允许热路径复用调用方提供的 `out` 对象；图边、恢复/视觉边和位移模板边因此必须在每次采样时完整覆盖分支专属元数据。开放或恢复路段显式清除 `covered / tunnelKind / tunnelProfileId`，恢复/视觉路段显式清除 `templateEdgeId`，位移模板路段则重新发布自己的 `runtimeKind` 与模板身份；前一个隧道或恢复样本不得污染相机、天气、地形切洞、物理或诊断。

立交图块固定预分配 `19` 个可复用直接批次，诊断分别公开预留批次和父图块当前提交的可见批次，零实例 `InstancedMesh` 不计入实时工作，不能再用 `children.length` 伪装实时绘制成本。精确转弯箭头与出口牌同时生效时，它们取代仅用于通用车道提示的编织引导层；已选路线、候选路线、`291×163` 投影、玩家箭头与 `200m` 标尺均不受影响，最坏转弯预览仍保持真实可见批次 `≤16`。

启动首段的 current/next 图块必须进入有界关键构建队列，不得在页面解析或运行时入口同步耗尽道路生成器。每次切片只推进受限工作，current 优先于 next，且两者都只在几何、支撑与诊断完整后原子发布；未完成记录保持隐藏，普通预热与恢复任务不得抢占这两个启动任务。resident tile pool 还会按目的图块 token 与恢复签名提前构建对向跨线路线及门架变体，current/next 对向变体以 `0/1` 优先级排在普通出口变体之前。跳台坡唇的硬实时调用只解析下一图块 token、提升已枚举目标并唤醒关键任务，不得同步调用 `prepareOpposingRecoveryPathPlan()`、变体 builder 或 resident 激活；这样起飞帧不会先切到对向签名，再被仍然权威的普通 `PathPlan` 切回或隐藏。High 实体标线几何也在 recovery 变体任务内提前生成，安装计时包含 finish 与 install，激活复用构建时的 graph/scoped-track 绑定。高速腾空或手工跳跃的路线游标可以先跨 tile，因此每帧更新必须接收由 `lastTakeoff.tileToken` 和未释放对向就绪门组成的 `pinnedTileTokens`。起飞 pin 保留到落地/终止，gate pin 保留到释放；两者使起飞源道路持续可见，并排在 future/warm 图块之前，但总驻留容量仍为 `maxTiles=3`。运行期若 current resident 尚在有界分片构建，上一帧完整 active 集合以 `continuityHeldTokens` 保持呈现，地图通过 `residentVisualMissing` 的 current graph fallback 先跟随权威路线；新 current 完整后先显示再撤旧。启动期没有 last-good 集合，仍保持未完成记录隐藏。落地采用先调用目的变体的精确就绪握手：至少要证明落地区可见并返回 `stableEdgeId / stableUntilEdgeS`；pending 不得让玩家从触地开始制动，只有已可见稳定段进入物理停车包络才取得安全制动权威，且完整几何、双腿支撑与诊断原子发布前仍不得越过边界。就绪后来源图块的跨线结构仍额外保留一个阶段，直到下一普通 approach 接管可见性，避免高视角看到道路或门架突然消失。图块 graph contract 以普通恢复路的最大可达拓扑发布 `decisionStructureNodeCapacity=9 / goreNoseCapacity=10`，即使 resident 由只有 `8 / 8` 的对向变体创建也不得缩容；激活先验证容量，再在固定槽内重写或归零，永久 rail-post 索引不会移动。诊断只读发布 `pinnedVisibleTokens`、`continuityHeldTokens`、坡唇请求/提升/已准备计数和运行时 pinned count。预热计划构建或路线解析的不变量异常必须保留原始错误向上抛出，不能缓存空计划或伪装成普通“暂未就绪”。

`requestOpposingRouteVariantPreflight()` 返回冻结且幂等的目的地握手，公开来源/目的 token、普通图块期望签名以及 `visualReady / collisionReady / presentedReady / landingSurfaceReady / ready / status`；其中碰撞就绪必须由目的图块真实的 `airborneLandingSurface` edge 证明。`markPresented()` 只能在一次真实渲染完成后记录当帧 active token 与签名，因而仅把对象设为可见或切换 resident 不能伪造 `presentedReady`。普通落地区必须同时是精确签名、当前 active、已呈现且有碰撞路面才能放行跳台；目的变体的 `ensureRouteVariantReadiness().ready` 同样要求精确 active 签名出现在最近呈现快照中，并始终保证 `ready=true` 时 `landingSurfaceVisible=true`。坡唇请求不会随 current/next 枚举重置：目的图块即使变成 previous，缺 resident 时仍排入关键整图构建，已有 resident 时持续排入精确对向变体；pending 只有在该签名真正安装后才释放。活动 builder 的 resident 与刚完成变体的同帧目标都不可被驱逐，所有保护仍在原 `maxTiles=3` 容量内优先淘汰推测图块，而不是扩大池。

同一 `+2` 预热目标一旦成为 next/current、落地预检或路线必需变体，池会在原 builder 上把 `buildSource` 提升为 `critical`，保留已经完成的生成阶段，取消尚未执行的 idle 回调并立即换成 `12` 步且总计不超过 `4ms` 的关键切片。builder 任一阶段异常都会记录首个错误的名称、消息、stack、目标和阶段，取消损坏 builder，并只保留一个重试目标；仍有路线租约的目标按 `32ms / 64ms` 最多重建两次，成功发布恢复计数，第三次失败则把最初异常交给外层运行时错误边界，禁止缓存空 resident 或无限循环。从 builder 创建到整图注册或恢复变体安装完成之间只存在一个资源租约：`finish()`、`setRenderQuality()`、旧 resident 替换或变体安装失败都由该租约恰好取消一次 builder；发布成功后再把视觉/模板所有权转交 resident，禁止双重 dispose。替换先从注册表摘除旧 resident 再调用其 disposer，因此即使 disposer 抛错，重试也不会再次释放同一对象。每次 idle、critical 和 retry 排期都持有唯一 ticket，绑定当时的路线 generation 与返回 handle；取消、优先级改排或路线失效会撤销当前 ticket。排期使用两阶段提交：调用 scheduler 前先把 ticket、kind 与 `SCHEDULING_HANDLE` sentinel 发布到当前槽，同栈 callback 因而可以立即认领并清槽；scheduler 返回后，只有原 ticket 仍持有 sentinel 才能安装真实 handle，否则返回值属于已经消费的旧请求，绝不能覆盖 callback 内递归排出的新任务。回调只有在 generation、ticket 对象和 handle 三者仍与当前槽位一致时，才可清除 handle 并执行。空/撤销 `PathPlan` 会先递增 generation、作废异步上下文，再取消三类任务和活动 builder；旧回调即使在新路线已经排出新 handle 后才执行，也只能无副作用返回，不能消费新 context、推进 builder 或重复排期。地图 fallback 继续提供权威路线，但同时用 `presentationDegraded` 与 `current-road-resident-missing / stale` 明确声明三维道路降级；池诊断公开提升、失败、重试、恢复、耗尽和 current 构建保护状态。重试等待、活动 builder 和 resident 仍分别只有一个、一个和最多三个，不扩大长期内存边界。

`getTextureRevision()` exposes an O(1) navigation texture-identity publication clock so the renderer can apply High filtering before the first draw. A complete tile registration increments it, as does an actual atlas material/texture identity swap on a registered visual. GPU texture count cannot substitute for identity because equal-count disposal and replacement leave it unchanged. Each visual owns a publication lease that survives recovery-route changes; callbacks from unregistered, failed, replaced, or pool-disposed visuals are rejected. Atlas release disconnects its language subscription and clears the callback. Geometry-only variant installation/activation, resident reuse, same-language atlas reuse, quality switches, and external HDR content-version updates do not increment the clock.

Continuous-load optimizations retain the existing Low/Medium/High material tiers, every structural model, shadows, and all `19` reserved batches. Film cylinders use absolute world coordinates, so whole-pool visibility restoration/hiding runs only on tile visibility transitions; variant layout writers still synchronize their own new matrices and visibility. Player-origin movement no longer repeats thousands of unchanged writes per frame. After each ambient-traffic matrix upload, Three's reused `computeBoundingSphere()` covers the exact geometry-centre offset, non-uniform scale, and submitted instance count. Main-camera and shadow passes cull that batch against their own frustums; main-view rejection must never change object `visible`. Diagnostics expose `routeCameraBlockerVisibilitySweepCount / ambientTrafficBoundsUpdateCount / ambientTrafficFrustumCulling`. Regression checks contain every submitted vertex within the current sphere and preserve both turn-back visibility and off-camera companions that remain shadow casters for a light.

Local enclosure reads the same scene rig's stable global-transmission uniforms and applies only attenuation not already present. Existing deep-tunnel dimming is not multiplied a second time, protecting Low/Medium readability without nearby spots. Standalone builds without a rig use outdoor transmission `1`; construct the rig before the road pool to share live ratios.

Static tunnel illumination now enters Three's indirect diffuse path, retaining actual albedo, vertex colors, tyre/stone detail, and AO response. `PI / 0.18` converts the legacy outgoing-radiance scalar to incident irradiance using fixed 18% reference gray, preserving baseline light between fixtures without dividing by actual material albedo or cancelling texture contrast; neither the base material nor the shader adds extra emission. An exception from any builder stage records the first error name, message, stack, target, and stage, cancels the corrupt builder, and retains only one retry target. A still-leased target rebuilds at most twice after `32ms / 64ms`; successful publication increments recovery evidence, while a third failure rethrows the first exception through the host runtime boundary instead of caching an empty resident or looping forever. Exactly one resource lease spans builder creation through whole-tile registration or recovery-variant installation: failures in `finish()`, `setRenderQuality()`, old-resident replacement, or variant installation cancel that builder once, while successful publication transfers visual/template ownership to the resident before any later cleanup can double-dispose it. Replacement removes the old registry owner before invoking its disposer, so even a throwing disposer cannot be called again by retry. Every idle, critical, and retry schedule owns a unique ticket that captures the current route generation and returned handle; cancellation, priority rescheduling, or route invalidation revokes that ticket. Scheduling uses a two-phase commit: the ticket, kind, and `SCHEDULING_HANDLE` sentinel publish before calling the adapter, allowing a same-stack callback to claim and clear its slot immediately. When the adapter returns, its real handle installs only if the original ticket still owns the sentinel; otherwise the return belongs to an already consumed request and may never overwrite work recursively scheduled inside the callback. A callback may clear its handle and execute only while generation, ticket identity, and handle identity all still match the current slot. An empty or revoked `PathPlan` increments the generation and invalidates async context before cancelling all three queues and the active builder. Even if an old browser callback runs after a new route has installed a new handle, it can only return without consuming the new context, advancing a builder, or duplicating scheduling. The authoritative map fallback remains available but now declares 3D-road degradation through `presentationDegraded` and `current-road-resident-missing / stale`. Pool diagnostics expose promotions, failures, retries, recoveries, exhaustion, and current-build protection. Retry wait, active builder, and residents remain bounded at one, one, and three respectively.
