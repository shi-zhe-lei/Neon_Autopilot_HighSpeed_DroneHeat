# Styles / 样式

## 中文

- 普通桌面横屏 `≥921px × 561–1,079px` 的最终样式使用 `296–320px` 仪表宽度；身份和音频分行，主要文案至少 `10px`，速度为 `36px`，音频按钮保持 `44px` 高。`.hud-primary-body` 从 `display:contents` 恢复独立滚动盒；右侧地图、操作区、领航详情按内容流排序并可内部滚动，防止翻译换行后固定偏移互相覆盖。此断点的地图使用相对定位，其他桌面布局保留固定地图合同；不改变移动端或 Film，也不修改玩法状态。

保存生产入口的响应式样式。布局、无障碍和 HUD 合同由浏览器夹具与静态测试共同验证。

- Neon 飞行 HUD 使用分区 Liquid Glass：透明且无 backdrop/filter/transform/perspective/containment 的定位祖先保留固定小地图合同；`.hud-primary::before` 承载左侧薄玻璃包络，`.hud-actions` 承载七键连续玻璃，小地图保持高密度但无祖先滤镜。`left / right / position / compass / input` 宿主继承运行时量化的透明度、边缘、高光、阴影、太阳反射颜色与位置，并由各自 `data-hud-contrast` 选择局部文字、边缘与表面安全 token。大包络的实际背景 alpha 限制在 `0.45–0.90` 验收区间，暗模式同亮度至少更通透 `0.015`；分数、距离、最高、成长、生命、FPS、横向位置、天气时间、地表接触与顶部身份标签统一使用同一自适应轻量单元格深度，不再混入孤立纯黑卡。只有指令、指南、罗盘和输入等独立文字承载层使用 `0.90 / 0.88`，白色高光与状态渐变保持低强度，内部单元格和按钮不重复创建 backdrop 层。系统配色不拥有游戏内权威；降低透明度、增强对比度、减少动态、强制颜色及无滤镜能力均有实色或系统色降级。
- `.hood-collision-guide` 实现低遮挡 `hood-collision-guide-v3`，仍是全视口、无交互的屏幕空间覆盖层，`hidden` 时必须 `display:none`。CSS 只消费运行时依据真实 `1.44 × 1.16 × 2.72m` 伤害碰撞尺寸、已提交 `PathPlan` 以及只读有界探针输出的四个短角标、两条下侧导轨及威胁状态；不得估算尺寸、路线曲率、未来跳台 lip/活动腾空轨迹或地面/顶棚风险，不得发起长跨度、高密度物理扫掠，也不得恢复完整 wireframe、远端门、中心轴或中央信息卡。角标内部及驾驶消失点没有背景、填充或文字，亮场分离只能给相同六条短路径增加轻量对比边。桌面宽度读数固定在视口下缘并避开驾驶输入，移动端必须隐藏。常态、`warning`、`danger` 只以静态青灰、琥珀、红色的线色和强度区分；样式不得自行按距离推断状态，不得添加脉冲、闪烁、位移或任何动画，也没有修改玩法或物理状态的入口。
- 生命与烛光卡的选择器和变量族严格分离。`.life-metric` 只按 `data-life-state="healthy|wounded|critical|depleted"` 及三个固定 `data-life-active` 槽消费 `--life-*`，用三段完整度轨、左侧状态边与损伤纹理形成离散变化；`.handling-metric` 只按 `data-handling-level="base|responsive|agile|elite"` 和连续 `data-handling-progress` 消费 `--candle-*`，用能量轨、星点与暖金→紫→青辉光形成连续变化。手机常驻卡保持相同的结构差异。紧凑、高对比、强制颜色和减少动态规则都必须按语义族分开，不得新增跨卡组合选择器、变量回退或从 HUD 外壳继承另一套状态。
- `.damage-impact-feedback` 是场景与 HUD 之间固定定位、中央透明且不接收指针的受击层；一次有效损伤只用合成器友好的透明度播放 `0.48s` 强边缘冲击，不增加模糊、backdrop 或输入遮挡。生命卡的 `data-damage-impact` 与护盾的 `data-invincible` 分别表达一次冲击和完整 `1.32s` 保护期：桌面使用青金晨星胶囊、环形进度与静默十分之一秒，手机折叠生命卡使用同一 `--life-protection-progress` 的 `16px` 环；车头将真实碰撞短括线改为青金保护态并只增加一条底部进度，不添加中央卡片或世界球壳。船体不以闪烁或频闪模拟无敌。减少动态取消部署动画和空间变化但保留静态进度；强制颜色以 Canvas / Highlight 保留非颜色语义。
- `.startup-loading` 是唯一初始可见层：它覆盖完整动态视口、吸收指针并按四向安全区收纳一个无操作控件的状态面板；开始页在加载期间必须由真实 `hidden + inert` 移出交互树。面板呈现模块、世界、道路、图形、首帧五个真实阶段和一条阶段同步飞行提示，不绘制百分比、剩余时间或由纯计时动画暗示的进度。提示区预留稳定高度，窄竖屏可自然换到三行且不得 `line-clamp`，矮横屏优先收起 orbit/eyebrow 等装饰而不能裁掉阶段、提示或完成即开玩的说明；切换不得推动卡片、产生页面滚动或新增交互目标。加载外层非 live，只有阶段状态播报，`role="note"` 提示保持 `aria-live="off"`。加载层使用 `z-index: 80`，低于更新提示 `90` 和致命恢复 `100`，但高于启动/暂停/结算共用层与 `z-index: 12` 的重开确认；`hidden` 时必须 `display:none` 且不能继续阻断指针。减少动态取消无限旋转、脉冲和提示过渡并直接替换文本；强制颜色以 Canvas / CanvasText / Highlight 和显式边框保留分类文字与提示层级，高对比、手机安全区和短横屏仍须保持完整可读。
- 启动页保持一个自适应交互控制台：`≥1280px` 的左侧非交互舞台只保留四枚静止细角标与 `290–330px` 轻量机体铭牌，不绘制圆环、轴线、脉冲或第二块厚玻璃卡；右侧 `560px` 卡继续独占交互。`900–1279px` 隐藏舞台并横排简报/配置，`≤720px` 竖屏贴底，`≤560px` 矮横屏压缩。开始页右上全屏工具键在所有断点保持不低于 `44 × 44px`，与 HUD 全屏键共享同一整页状态，但始终位于启动 action 之外，不挤占暂停或结算动作区。只有玩家主动点击才请求进入或退出全屏；样式与状态同步不得造成自动请求，也不表达或推进 `ready / committing / commit`。加载完成的普通入口必须先解除开始按钮禁用，再显示这张开始页，最后隐藏加载层；样式不得产生“开始页已露出但按钮仍禁用”的过渡帧。`data-overlay-mode` 只切换启动、暂停和结算的色调与区块；暂停模式把继续、重新开始和手册排成三个不低于 `44px` 的操作目标，并在其他模式以真实 `hidden` 状态移除重开按钮。暂停卡必须相对扣除四向安全区后的动态视口可用矩形水平、垂直居中；手机竖屏与矮横屏都不能继承启动页贴底规则，内容超高时只滚动卡片内部。重开确认是 `z-index: 12` 的独立层，两个操作目标不低于 `48px`，`≤480px` 时单列堆叠。`committing` 同步锁定配置与启动 action；减少动态关闭入场、呼吸和旋转动画，强制色彩隐藏纯装饰舞台。
- 语言入口只属于启动/暂停共用层、手册、音乐库、重开确认、更新与恢复模态面板，实时 HUD 内不得出现。按钮保留 `44 × 44px` 触控热区，但通过内缩伪元素把可见药丸压到约 `34 × 28px`；中文界面显示“英”，英文界面显示“ZH”。窄屏遥测使用真实 `minmax(0, 1fr)` 列，英文操作名和音乐元数据最多换两行，地图、天气与状态值允许在自身卡片内自然断行，不得横向溢出或裁掉语义。
- v16 飞行手册保持固定三行外壳与唯一 `.guide-panels` 内容滚动区；页头、章节入口和上一章/下一章不得随长章节滚走。玩家可见的 Essential/“必会”默认显示 `16` 项，Full 范围在界面中标为 Complete/“完整”并显示同一账本的全部 `43` 项；`data-guide-view="essential"` 配合真实 `hidden` 只隐藏其余 `27` 个参考节点，样式不能复制、重排或改写账本。只读航程摘要、两枚阅读范围按钮、五步 60 秒快速上手、P/M 四象限权威矩阵和循环章间按钮都属于手册覆盖层，交互目标不小于 `44px`，玩家说明正文不小于 `12px`；覆盖层关闭时必须 `display:none`，不能残留输入或焦点遮挡。非矮横屏的 `≤720px` 手机将四章排成单行四列，以一行阶段/权威/速度/生命烛光/制动摘要配合独立“下一步”形成紧凑只读区，正文和快速上手/权威矩阵改为单列，保留前后章按钮并隐藏与页头关闭键重复的返回控件。`320×568` 最小屏只隐藏与段落标题重复的快速上手引导句，五条编号规则必须全部保留，且第一个编号步骤在内容滚动前完整可见。`721–1100px` 竖屏小 iPad 使用扣除四向安全区后的全高外壳、`180px + 正文` 双栏和独立内容滚动；更宽布局继续使用 `232px + 正文`。`≤560px` 矮横屏优先改用 `146px` 章节侧栏、紧凑只读摘要及正文，页脚只保留前后章。所有布局服从四向安全区与 `100vh → 100dvh`，但 CSS 规则本身不等同于 Safari 安全区、动态浏览器栏、旋转或触控实机证据。
- “天气与世界”章的五张 `world-swatch` 是 `aria-hidden` 的 CSS 微型场景，只解释已发布的区域配对、同源地图、地标生态、山体廊桥和环境船流。视觉子节点与 `data-world-preview` 钩子不能增加交互目标、远程图片依赖或新玩法语义，也不能成为第 `44` 个玩家功能 ID。
- 飞行数据舱以一个连续包络组织速度、生命、距离、成长、FPS 与天气；推进核心固定嵌在 `speedometer-body` 内，宽屏使用第三列，紧凑模式只在同一卡片内折为第二行，不占用新的 HUD 网格轨。其零烛光 `1,800–12,000 rpm` 转速带会随共享成长档案连续扩展，上限渐近 `15,000 rpm`；推力与带符号净加速度仍只投影运行时权威推进状态，并与飞船及尾焰共源。样式和 ARIA 上限读取当前档案，不得从按键或速度推断状态。横向位置是带左/零点/右刻度的 `10–14px` 玻璃轨，圆形指针只改变 `left` 并始终留在端点内。指令舱继续使用图标、名称、状态和键帽；启动、继续或再次启航时，它从终点下方 `16–26px` 以 `420ms` 合成器位移平滑上滑，不再只靠透明度闪现，也绝不把变换施加到 HUD、地图或导航定位祖先。`921px+` 横屏在 `561–1,079px` 高度继续使用紧凑双翼和右侧完整战术列，只有 `1,080px+` 才进入完整四列桌面布局，避免领航详情被视口底部裁切。关闭的自动领航详情仍以 `0fr` 和真实 `hidden` 退出；开启时只由 `.auto-panel` 这一层 Liquid Glass 承载，`auto-panel-liquid-enter / auto-panel-liquid-rim / auto-panel-liquid-sweep / auto-panel-content-settle` 四个命名动画只改变 `opacity / transform`，从而兼容 `hidden → visible` 的弹出顺序，内层状态单元不再创建 backdrop。减少动态让指令舱和领航详情直接呈现终态；减少透明度、无 backdrop 支持与强制颜色分别使用实色或系统色回退。推进指针与填充也在减少动态时取消过渡，并在强制颜色下使用系统 `Highlight`；透明定位轨本身不绘制背景，地图 Canvas 与全部 fixed 定位祖先均不得获得滤镜、backdrop、变换、透视或 containment。
- 推进核心的 `data-propulsion-state="creep"` 使用稳定浅绿色调区分真实1挡怠速蠕行与青色踩油推进、紫色滑行及红色制动；它只投影运行时语义，不闪烁、不启动循环动画，也不从速度自行推断。
- 自动领航指令 HUD 的桌面与双轴至少 `700px` 的 iPad 详情完整显示稳定策略、风险等级与百分比、横向/纵向权威、制动原因以及最近威胁/TTC。风险条使用语义 meter，并以 `30% / 58% / 82%` 三条刻度分隔安全、留意、警戒、危险四级；横向与纵向权威、制动和威胁各自使用独立语义轨，手动权威为青、自动/巡航为金，真实制动或高威胁为红。`data-risk-level / data-lateral-authority / data-longitudinal-authority / data-brake-mode` 是样式消费的唯一状态合同。高频详情本身保持非 live，只有相邻的屏幕阅读器状态节点播报离散的权威或制动变更。手机只在 P 领航开启时显示移动专用紧凑状态胶囊；P 关闭时胶囊必须由真实 `hidden + inert + aria-hidden` 移出布局，M 自动油门的独立状态不能让它复现。胶囊仅保留意图、稳定风险和真实制动摘要，不复制四格桌面详情，也不运行桌面 Liquid Glass 弹出动画；完整权威与威胁详情继续属于桌面和大 iPad。
- `html[data-mobile-cockpit="true"]` 是手机/iPad 最终级联权威，但手机可见结构使用独立 HUD 外壳而不是缩放或跨列复用桌面双翼。手机常驻窄 glance、唯一航路/警示槽和移动操作坞；领航、自动油门、视角、暂停保持至少 `44px` 直达目标，灯光、全屏、仪表与地图进入移动详情。航路/警示槽平时显示下一指令与距离，限速或安全制动出现时原位替换普通航路文案，并位于常驻 HUD、详情和驾驶键之上而不与它们重叠。`--safe-top/right/bottom/left` 配合 `viewport-fit=cover` 约束每条边，运行时发布的 `--mobile-vh` 与 visual-viewport 宽高/偏移变量来自相机、Canvas 和后处理共用的同一测量快照。竖屏保留顶部 glance、航路槽与紧凑 `2×2` 操作坞；矮横屏把左右翼实际宽度作为顶中航路的左右保留量，`≤699px` 宽时再把航路移到头栏下方。仪表/地图详情从航路或可见领航胶囊底边起算，并在中央换挡器或双层驾驶键上方结束；短边 `<700px` 的两块详情互斥，双轴 `≥700px` 的 iPad 可独立展开并使用 `80–88px` 驾驶键。双轴 `≥700px` 的触控 iPad 还把中央 MT/AT 换挡器与左右底排驾驶键对齐到同一安全底边；换挡器始终水平居中，模式切换只改变其向上高度，Film 与旋转不得改变底边。iPad 横屏航路槽与左右 HUD 共享安全区顶线，竖屏槽位于顶栏下方；两者保持 `64px` 高度且不因文字或工具抽屉改变位置。连接 Magic Keyboard 后是否进入该层由运行时触控能力决定，CSS 不以 `hover:none` 作为唯一入口。
- 桌面电影 HUD 是宽度不超过 `390px` 的左上边缘监看台：速度、实时挡位和当前换挡范围组成跨三行的主卡，得分、烛光成长和生命各自占据右侧次级卡；P/M/F 位于控制轨首行，暂停与全屏平分第二行，因此镜头名、驾驶权和工具状态都不会再压成一排。高度 `≤620px` 的非移动画布统一收紧到 `372px`、`43px` 状态行和较小数字，但不隐藏权威值或驾驶操作，也不恢复五键单行。移动工具抽屉仍在 glance 原位显示并把它从视觉与命中树暂时移开；普通手机以 `2px` 间距和内边距形成 `234px` 五列单行，`≤359px` 窄竖屏及矮横屏用 `144px` 三列两行，因此抽屉不再压住下方航路。双轴 `≥700px` iPad 恢复五列单行，外宽严格包含五个 `56–60px` 目标、四个间距、内边距与边框。全部目标服从四向安全区；四枚常驻安全操作与 `C` 视角键的布局、尺寸和语义保持不变。
- 战术导航使用一个稳定的 `.minimap-panel` 外壳：标题/模式、方向指令、双 Canvas 视口、DOM 图例与三项路线状态按固定顺序排布，模式和威胁只改变色调，不重排语义。Canvas 只绘制地图内容，不再重复绘制障碍/烛光图例；已选、候选、障碍、烛光与环境船流由外层 `.minimap-legend` 持续解释。
